# 0008 — Règles des sites (`WEB*`) : vérifiées par le socle, pas par `ocots-lint`

**Date** : 2026-10-27 — **État** : proposée (#78)

## Contexte

`ocots-conventions` a désormais `site.md` (`WEB1`–`WEB20`), pour les sites
web des cours construits sur `ocots-site`. Chaque règle y dit ce qui la
vérifie (« Vérifié par ») : un test du socle, `verifieCours` et
`verifieModeles` (lancés par `npm test` du cours), la fumée du socle, ou la
relecture. Quatre règles notent un « lint possible » : hauteur en pixels d'un
canevas (`WEB3`), `font-size` dans un module (`WEB6`), couleur en dur
(`WEB11`), apostrophe droite dans un texte du site (`WEB9`).

Les pistes de #78, une fois `site.md` écrit :

| Piste | Où c'est vérifié |
|---|---|
| `site.config.js` conforme au schéma | `verifieCours` (`valideConfig`) |
| clé de préférences `<id>.illustration.<page>` | construite par `demarreIllustration` du socle : plus rien à vérifier dans le cours |
| chaque illustration du catalogue a son module | `verifieCours` (charge chaque module sous Node) |
| liens « ← Accueil » | les modèles du socle, comparés par `verifieModeles` |
| couleur en dur, mention d'un autre cours | « lint possible » : rien encore |

## Options

| | A. Le socle vérifie | B. `ocots-lint` lit aussi le site |
|---|---|---|
| Lecture | JS chargé sous Node par `verifieCours`, CSS lue par les tests du socle | un second lecteur (`.js`, `.css`, `.html`) à côté de l'arbre LaTeX |
| Où ça tourne | `npm test` du cours, dans sa CI déjà en place | `verifier` hebdomadaire et en PR, sur un autre type de source |
| Dépendance | aucune | un analyseur JS ou CSS (décision à écrire), ou des regex sans garantie |
| Versions | la règle et son test montent ensemble avec l'épingle du socle | règle dans les conventions, vérificateur dans `ocots-lint`, code dans le socle : trois versions à accorder |

## Décision

**A.** `ocots-lint` reste l'outil des documents LaTeX. Une règle `WEB*`
mécanique devient un test du socle (`ocots-site`), lancé par `npm test` de
chaque cours : le contrôle est écrit à côté du code qu'il contrôle, dans le
langage de ce code, et monte avec lui. Les quatre « lint possible » de
`site.md` y vont aussi, le jour où on les outille.

`ocots-lint couverture` lit `site.md` quand les conventions l'ont : les
règles `WEB*` y sont listées « hors ocots-lint », comptées à part, pour que
le tableau ne les fasse passer ni pour vérifiées ni pour oubliées. Le détail,
règle par règle, est le « Vérifié par » de `site.md`.

## Conséquences

- Aucun vérificateur `WEB*` dans `ocots-lint`, aucune dépendance nouvelle.
- `couverture --support site` liste les `WEB*`. Des conventions sans
  `site.md` (épinglées avant) restent lisibles.
- Un « lint possible » de `site.md` s'ouvre en issue dans `ocots-site`.
